# Skill → device resolution — how it works now

Every "this skill affects these devices" list in the console and in the skill reference comes
from **`tools/device-console/skilldev.json`**, which is generated by
**`tools/device-console/gen_ix.py`** and committed. (An earlier version of this document
claimed the file had no generator — wrong: `gen_ix.py` always emitted it, but wrote it to a
session scratchpad where it looked orphaned. It now writes next to the script, and
`gen_tree.py` reads it from there.)

The resolver was rebuilt on 2026-08-05 against the project owner's in-game review of the same
date. All findings from that review are either fixed by a generic rule or carved out
explicitly below.

---

## 1. Resolution rules (`gen_ix.py`)

Resolution happens **per effect, not per effect group**; a group's device list is the union of
what its effects reach. Each effect starts from a base set:

| gate | base set | scope tag |
|---|---|---|
| `required_skill_id` | devices whose item `skill_id` matches (the weapon family) | `skill` |
| `required_category_value_id` | devices producing that effect category | `category` |
| ungated | `SEMPRED`: prop semantics (damage props → `dmgcls`, see below; 208 → timed effects, 203/4 → cooldown, 242/322 → power cost, pet props → pets, …) | `tree` |

**Damage props (212/214/321, and 352 ungated) key on `dmgcls`** — the attack classes of the
modes that actually deal damage. Each mode (carrier and payload alike) is classified with the
same rule the device model uses (`gen2.py hit_of`, mirroring the server's
`TgDeviceFire__GetEffectGroup`): melee (atk 170/372) never promotes, a ranged mode (85/177)
with a prop-6 blast radius is AOE, else it stays ranged. A mode counts only if it carries
negative Health/Power (props 51/211) — the only props the bench's damage bucket ever
modifies. Three traps this rule exists to avoid, all shipped at some point:

- **Raw attack type is how a mode AIMS, not what it hits.** Every AOE weapon also carries
  atk 85/177, which put MagmaLance, Rumbleblaster and Poison Aura under ranged damage.
- **A harmless spawn must not promote.** The sniper rifles' projectile chain reaches
  `YA_AOE_AmmoCrate` (prop-6 radius 40), which made Ballista, Scorpia and the Dweller read
  as AOE weapons — in the bench too, via `devmeta.aoe`.
- **A damage *buff* is not damage.** Boost Beam's "Dmg +10%" chip is prop 65 granted to an
  ally; only negative 51/211 qualifies.

`devmeta.json` exports the corrected `aoe` flag, which is what `bench.js propList` uses to
pick the damage-modifier bucket — so this classification is the compute path, not a display.
A projectile-spawned bot (Spider Grenades' spiders, `projectiles.spawn_bot_id`) marks the
carrier as a pet and is not payload: its damage takes Pet Damage (350), same as turrets.

Then two narrowings apply on top:

- **`ACTPRED`** — a gated family is wider than the effect, so the effect's property must mean
  something on the device: a lifetime modifier (208) needs a timed effect, a radius modifier
  (352) needs a radius, cooldown/power modifiers need a cooldown / power cost. This is what
  drops Healing Wave and BioFeedback Beam (instant heals) from Heal Durations, and Force Wall
  (fixed size, no radius prop) from Station Radius — no special cases.
- **`property_value_id`** — an effect carrying one is scoped to that effect **category** and
  may not touch any other (`damage-pipeline.md` §15.2). Heavy Impact's potency is pv875
  Knockback, so of the Assault Guns it reaches only the guns that actually knock back;
  Poison Duration's pv303/305/879 drop every healing device; Buff Enhancement's
  pv1283/935/775 drop the heals that carry no buff; Eagle Eye's pv769/986/875 reach the
  Ballista's debuff but not the plain Recon SMGs.

Two supporting facts the resolver needed:

- **A directly-placed deployable is its own payload.** Device categories, radius, and timed
  effects are read from the carrier plus its payload chain — projectiles (`device_projectile_id
  → spawn_item/spawn_deployable`) *and* direct placement (`mode deployable_id → deployable's
  device`). That is where the stations' aura categories live (Medical Station cat 1324 on dev
  2064, Sensor 1326, Power Station 1327 — exactly Station Buff's pv scopes) and where Force
  Wall's deployable (dev 1400) shows no category and no radius. `bot_id` stays excluded: a
  turret is a separate combatant.
- **Only the Crescent jetpack is equippable.** The other 12 jetpack variants sit in the
  inventory table but not in the live pool (same rule as `gen2.py`); they were padding Jetpack
  Power to 16 devices and Super Flight to 4. They were also the only devices with no icon in
  `deviceimg.json`, so that gap closed with them.

## 2. Explicit carve-outs (`EXCLUDE` in gen_ix.py)

Two facts no field in the data expresses, hard-coded with the evidence:

- **Bio Rifle Range (674) excludes the Pain Gun.** The tooltip says so; the gate is Medic
  Guns (405) and the Pain Gun carries 405. (The Pain Gun rightly stays under Death Medic and
  Poison Duration — it does apply Disease.)
- **Group Heal Savior (852) excludes Triage Wave.** Measured on branch `device-usage-metrics`:
  a solo Triage rescue applies eg 22375 and never eg 16587, while Healing Wave and Healing
  Grenade both proc it. All three carry identical family-252 linkage in the data, so the
  mechanism is unestablished and the carve-out is empirical.

## 3. Kept on data grounds (review flagged, data disagrees)

- **iMINIGUN / Helot Minigun / Stormer stay under Heavy Impact.** The review grouped iMINIGUN
  with the no-knockback guns, but it carries two cat-875 knockback effect groups (eg 7295 /
  9352, prop 295 = 1.0), Helot carries 1.5, Stormer 1.0. Rhino SMG carries none and dropped.
- **Targeting System stays under Stealth Restealth.** Its item `skill_id` is 287 (Stealth
  family) and the gated effect is a power-cost cut, which it can take. The engine's
  GetBuffIndex match rule would apply it in game.
- **Deconstructor stays under Super Ninja.** Its item `skill_id` is 328 (Explosives), and the
  group's remote-activation / deploy-time / cooldown effects can act on it.

If any of these three is disproven in game, it joins `EXCLUDE` with the measurement.

## 4. Corrections that moved out of the render layer

`gen_skillref.py` previously patched over the resolver at render time; both patches are now
upstream and deleted from the page generator:

- attack-type matching for damage props (212/214/321) — now `SEMPRED`
- the live-pool filter (jetpack variants) — now the inventory filter in `gen_ix.py`

Still render-side, correctly: `HIDE_DEV` (HUMAN BASE ATTRIBUTES is real data but not
player-facing), class-compatibility filtering per displayed class column, and the `NOTES`
annotations (674 and 852 explain their carve-outs on the page).

**Super Healer's +50 on-hit heal lands on the CASTER, not the target** — its group is type
759 (successful-hit self-buff), which `gen_skillref.py` keeps in `SELF_EGT` so no side label
is shown.

### Collapsing repeated effects is gate-aware (2026-08-05)

The page shows one line per distinct effect value, which stops Jetpack Power printing
"−30% Power Pool Cost" four times. The first version keyed only on property and value and
**dropped the gates**, which was wrong for **Death Medic**: it carries +200% potency *twice*,
once gated to Medic Guns and once to Area Poisons, and merging them into a single unlabelled
line reads as one buff when a medic can carry one family without the other.

The group key now includes the gate with a leading class word normalised away
(`assault|medic|recon|robotic|robotics`). So `Assault Jetpack` / `Medic Jetpack` / … collapse
to one line labelled `Jetpack`, while `Medic Guns` and `Area Poisons` stay apart with their own
labels. Checked against the in-game tooltip: Death Medic now renders all six of its effects with
the same gates the game lists, and Eagle Eye's two potency entries — same gate, different values
— correctly stay separate.

### Prop 376 renders by its scope, and pv is part of effect identity (2026-08-05)

The game never shows prop 376 as "potency". It names the **category the potency is scoped to**:
Death Medic's reads **"Disease"** (its effects carry `property_value_id` 305), Super Destroyer's
reads "Movement Penalty" (`damage-pipeline.md` §11). Implemented at the point names are
produced — `gen_tree.py` carries `pv`/`pvn` on every fx entry and names prop 376 by its scope,
so the reference page, the character sheet and the tree tooltips all agree. Other pv-scoped
props keep their name and show the scope as a chip: Eagle Eye's two +20% duration effects are
"Effect Lifetime Modifier" scoped to General Debuff and to Additional Damage.

Carrying pv exposed that it was **missing from every identity key**, and same-value effects at
different scopes were collapsing into one:

- Station Buff granted 2 of its 3 station buffs (+20% Station Damage swallowed +20% Station
  Healing; +50% Station Protection survived on value)
- Stim Boost's two +50% potencies (Personal Damage Buff / Stim Boost) read as one
- Buff Enhancement's 3+2 scoped +40%s read as two
- Eagle Eye's +30% General Debuff and +30% Additional Damage read as one

`pv` is now in the dedup key in `gen_tree.py` (which keys on the whole effect, not a summary),
the display-group key in `gen_skillref.py`, and the character-sheet aggregation key in
`builder.js` — different scopes are separate lines and are never summed. The bench already
scoped correctly (`fpv !== cat` in `GA.resolve`).

### Benefit is the arrow, the sign is the data (2026-08-05)

A minus is the calc method, not a judgement: −15% Power Pool Cost is a gain, −5 Protection on
the enemy is a gain, −35% GroundSpeed on yourself is a cost. `tools/device-console/benefit.py`
is the single source: benefit = (who it lands on) × (direction) × (stat polarity), with
polarity split into OWNER_COST (cooldowns, power costs — yours even on an unprefixed chip),
INFLICTION (knockback, CC, extra damage taken — the recipient wants less, so on an enemy more
is a gain), and HIGHER_BETTER. Scoped potency/duration effects classify by their `pv`
category: penalties on you (`Movement Penalty`, `Shield Movement Penalty`, `Stim Resistance`,
`Regen Damage Penalty`) are wanted smaller, everything else bigger.

Rendering: green ▲ = helps the build, red ▼ = costs it, the literal +/− stays. Every
reference-page line carries a who-chip (you / allies / enemies). Unclassified stats render
amber with a `polarity?` chip — currently only Threat (prop 421 / category 1601, benefit
depends on whether the build wants aggro) — and a "bad on somebody else" reading (a skill
apparently buffing enemies) demotes to the same flag instead of being asserted, since no
skill does that on purpose. One genuine red exists: Escape Durations' +30% duration is
scoped to Stim Resistance too, so it stretches the post-stim self-debuff along with the
escape effects.

The console reads the same tables via `window.__POLARITY__` (injected by `gen3.py`): card
chips carry small ▲/▼ arrows (side = self prefixes / self effect-group types / owner-cost
props, else the mode's target type), the character sheet arrows its totals and per-source
values, and the bench seeds its owner-perspective `lower` flag from OWNER_COST.

## 5. Where this lives

All generated data lives in `tools/device-console/out/` (covered by the repo-wide `out/`
ignore); only `skilldev.json` is committed, beside the scripts. No generator reads from or
writes to a session scratchpad any more.

| file | role |
|---|---|
| `tools/device-console/gen_ix.py` | the resolver — emits `skilldev.json` (next to the script, committed), plus `out/ix.json` / `out/ixraw.json` / `out/devmeta.json` for the console |
| `tools/device-console/skilldev.json` | generated skill → device map; regenerate, don't hand-edit |
| `tools/device-console/gen_tree.py` | reads `skilldev.json` script-relative; emits `out/tree.json` |
| `tools/device-console/gen_skillref.py` | builds `out/skill-reference.html` from `out/tree.json` |

The reference page is published at
`https://claude.ai/code/artifact/1ce7a67c-4e92-47e3-b437-9850316cbb50`.
